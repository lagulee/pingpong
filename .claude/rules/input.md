# 타격 시스템 사양 (7단계: 구질 버튼)

> **조작 모드 (v7.4, 설정 ⚙)**: 아래 내용은 **고급 모드**(Q·W·E·R 구질 버튼)다. **기본 모드**(기본값)는 v6.3처럼 드래그 방향·곡률·속도로 구질을 정한다 — 맨 아래 "기본 조작 모드" 참고. 판정 이후(조준·λ·회전 누적·판정용 회전)는 두 모드가 같다.

구질은 **버튼**이 정하고, 스윙은 **세기·좌우 조준·타이밍**만 정한다. 드래그 방향·곡률은 구질 판정에 쓰지 않는다(v6.3까지의 "드래그 방향으로 구질 자동 판정"을 7단계에서 바꿨다).

## 기본 조작

| PC | 모바일 | 동작 |
|---|---|---|
| 마우스 위치 | 손가락 위치(+ `TOUCH_OFFSET_PX` 위) | 라켓 위치(좌우·높이). 앞뒤는 자동(예측 정점) |
| 왼쪽 버튼 누른 채 드래그 | 손가락으로 쓸기 | 스윙. 라켓이 공에 닿는 순간 타격 |
| 왼쪽 버튼 누른 채 멈춤 | 대고 멈춤 | 블록 (구질 버튼과 상관없음) |
| 버튼 없이 공이 닿음 | 손가락을 뗀 뒤 | 약한 블록 |
| **Q** | 화면 버튼 **드라이브** | 강한 탑스핀 |
| **W** | **커트** | 강한 백스핀 |
| **E** | **사이드** | 강한 횡회전 |
| **R** | **스매시** | 스매시 (높은 공만) |
| 구질 버튼 없음 | 구질 버튼 없음 | **일반 스윙**: 무회전 |

- **두 버튼을 동시에**(v7.3, `resolveShotKeys`): **W+E = 사이드 커트**(횡+백), **Q+E = 사이드 드라이브**(횡+탑). R(스매시)이 눌려 있으면 스매시(섞이지 않음). Q+W는 나중에 누른 것. 하나를 떼면 남은 버튼의 구질로 돌아간다. 같은 버튼을 두 곳(모바일 단일·조합 버튼)에서 누를 수 있어 누른 횟수를 센다(`createShotKeys`). 창이 포커스를 잃으면 모두 놓은 것으로 본다.
- **인정 시간**: 접촉 직전 `BUTTON_WINDOW`(0.08 s) 안에 눌려 있던 가장 최근 버튼(창 시작 순간의 상태 포함). 키를 조금 일찍 떼도 인정한다(`buttonAt`).
- Ctrl·Alt·⌘와 함께 누른 Q·W·E·R은 무시한다(Ctrl+R 새로고침, Ctrl+W 탭 닫기).
- 시점(드래그 속도 보정 `dragScaleFor`)과 터치 감도(`touchSpeedScale`)는 그대로다. 로봇·서버는 1.

## 샘플 형식

마우스·터치·로봇 모두 같은 샘플 `{ t, x, y, b, k }`: t 게임 시각, (x, y) 라켓 평면 위 좌표(m, 좌우·높이), b 마우스 버튼(손가락 닿음), **k 구질 버튼**(`'drive'`·`'cut'`·`'side'`·`'smash'` 또는 null). 버튼을 누르거나 떼면 라켓이 멈춰 있어도 그 순간 샘플을 남긴다(`mark`).

## 구질 판정 (`judgeType(drag, z, params, pressed, button)`)

| 조건 | 결과 |
|---|---|
| 마우스 버튼 없음, 또는 스윙 최고 속도 < `BLOCK_SPEED` | **블록** (버튼과 상관없음) |
| R + 스윙 속도 < `SMASH_SPEED`(마우스)·`TOUCH_SMASH_SPEED`(터치), 방향 무관 | **일반** (`quality.smashSlow`). v7.3 기본값은 둘 다 **0** = 휘두르기만 하면 스매시(느리면 약한 스매시, `SMASH_V_MIN`) |
| R + 공 높이 ≥ 네트 + `SMASH_MIN_HEIGHT`(빨간 고리) | **스매시**. 사람은 화면 고리(예측 정점) 높이로 판정한다(v7.2): 빨간 고리면 맞은 높이가 네트 + `SMASH_RING_FLOOR`(0.25 m) 이상이기만 하면 스매시 |
| R + 공 높이 < 네트 + `SMASH_MIN_HEIGHT`(노란 고리) | **실타** — 네트 아랫부분으로 꽂힌다 (무조건 네트) |
| Q / W / E | 드라이브 / 커트 / 사이드 |
| W+E / Q+E | 사이드 커트 / 사이드 드라이브 (v7.3 조합 구질) |
| 버튼 없음 | **일반** |

- 스윙 최고 속도(`PEAK_DT` 구간, 80 ms 창)로 세기 $s$를 정한다. 좌우 성분은 좌우 조준(`AIM_X_DRAG`), 사이드 회전 방향(오른쪽으로 쓸면 진행 방향 왼쪽으로 휨, 좌우 성분이 거의 없으면 탁구대 가운데 쪽)에 쓴다.
- v6.3의 `LOW_SMASH_MISHIT`·`DIR_SIN`·`CURVE_MIN`·`DEPTH_GAIN`은 없앴다. 곡률(`analyzeDrag`의 `kappa`)은 계산만 남아 있다.

## 판정용 회전 (들어온 회전)

받는 쪽은 상대가 쳐 보낸 회전에 공기 중 감쇠만 곱한 값을 "들어온 회전"으로 읽는다:

$$\vec\omega_{in} = \vec\omega_{launch}\,(1 - d\,\Delta t)^{n}\cdot C \qquad (d = \texttt{SPIN\_DECAY},\ n = \text{지난 물리 스텝 수},\ C = \texttt{SPIN\_CARRY} = 1)$$

- 이유: 물리 바운드 마찰(접점 미끄러짐을 구름 상태까지 없앰)이 백스핀을 거의 지워(커트 28.5 → 2.9 rps), 공의 실제 회전으로는 회전 읽기·누적이 성립하지 않는다. `MU_TABLE`을 0.05까지 낮춰도 절반만 남고 커트의 "멈칫"이 사라져 쓰지 않았다(B안).
- 공의 비행·바운드·화살표는 물리 회전 그대로다. 판정·누적·로봇 읽기·꼬리 색·회전 표지만 $\vec\omega_{in}$을 쓴다.
- 출발점은 `game.inSpin = { t, spin }`(match.js `applyHit`, ai.js `incoming`), 계산은 physics.js `carriedSpin`, 판정은 `classifyShot(…, { spinIn })`. 토스한 공은 null(물리 회전 = 0).

## 들어온 회전의 효과 (λ)

나가는 공 = 조준(`solveArc`/`solveAim`) + λ × 들어온 회전의 효과. 효과는 라켓 면(`*_PITCH`)과 라켓 속도(면 법선 × 나가는 속도)로 `P(ω_in) − P(0)`를 계산하고, **탑·백 성분과 횡 성분을 따로** 계산해 각자의 λ를 곱한다(`incomingEffect`).

- 라켓 속도를 넣는 이유: 정지 라켓으로 재면 바운드 뒤 느린 공(1~2 m/s)은 법선 충격량이 작아 효과가 거의 없었다(일반 스윙으로 커트를 쳐도 네트에 안 걸림).
- 효과는 회전에 거의 비례해 커진다(약 0.05 m/s/rps, 100 rps 근처에서 마찰 한계로 포화). 그래서 회전이 쌓일수록 잘못 받은 공의 실수가 커진다.

| 구질 | 속도 (m/s) | 기본 회전 (rps) | 상한 `SPIN_CAP` | 누적 `STACK` | λ 탑 | λ 백 | λ 횡 |
|---|---|---|---|---|---|---|---|
| 일반 | 2.5–5.8 (드라이브와 같은 정점) | 0 | — | — | 1.0 | 1.0 | 1.0 |
| 드라이브 Q | 2.5–5.8 | 탑 30–80 | 100 | 0.5 | 0.1 | 0.2 | 0.4 |
| 커트 W | 2.3–4.1 | 백 25–55 | 70 | 0.7 | 0.3 | 0.1 | 0.4 |
| 사이드 E | 2.5–5.0 | 횡 35–65 + 탑 10–20 | 70 | 0.6 | 0.4 | 0.45 | 0.15 |
| 스매시 R (높은 공) | 10–15 | 탑 5–15 | — | — | 0 | 0 | 0 |
| 블록 | 반사 | — | — | — | 0.1 | 1.0 | 0.5 |

- 커트 상한 70: 백스핀 100 rps면 마그누스 상승 가속도($K_M\omega v \approx 7.5$ m/s²)가 게임 중력(5.88)보다 커서 공이 떠오른다.
- 사이드 상한 70: 90이면 쌓인 횡회전으로 크게 휘어 사이드 → 사이드도 27%가 아웃됐다.
- 드라이브 최소 회전은 30 유지(계획의 40은 탁구대 높이 5 cm 낮은 공 드라이브가 네트에 걸려 사람 대역 98%를 못 지킴).

## 조합 구질 (v7.3)

- `sidecut`(W+E, 모바일 "사이드 커트" 버튼)·`sidedrive`(Q+E, "사이드 드라이브"): 속도·정점·깊이·면은 바탕 구질(커트·드라이브), 회전 = `COMBO_MIX`(0.75) × (바탕 회전, 사이드 회전). 두 성분이 각각 같은 종류로 쌓인다(백·탑은 커트·드라이브 누적, 횡은 사이드 누적). λ는 바탕 구질과 사이드의 평균. 소리는 사이드 소리. 서브에도 쓸 수 있다.
- 측정(사람 대역 IN %, 무회전/탑45/탑100/백30/백70/횡40/횡90): 사이드 커트 89/58/0/95/94/99/86, 사이드 드라이브 96/98/17/85/0/100/100. 사이드 커트는 백스핀·횡회전 공에, 사이드 드라이브는 탑스핀·횡회전 공에 강하다.
- 로봇은 조합 구질을 쓰지 않는다(받기만 한다).

## 빨간 고리 스매시 (v7.3)

- 사람의 스매시는 화면 고리 높이(`ringZ`)로 판정하고(v7.2), 맞은 높이 하한 `SMASH_RING_FLOOR` 0.25 → **0.05 m**(네트 위, 탁구대 위 0.20 m).
- **스매시 속도 보조**: 오차까지 붙인 실제 발사 공이 상대 코트에 떨어지지 않으면 0.5 m/s(`SWING.SMASH_ASSIST_STEP`)씩 `SMASH_ASSIST_V`(6 m/s)까지 늦춰 다시 조준한다. 낮은 타점·늦은 타이밍에서도 들어간다(대신 느려진다).
- 측정(사람 대역, 맞은 높이 0.3~1.1 m × 위치 × 스윙 속도·방향 × 타이밍 × 회전 4,536타): v7.2 35.7%(일반 50%: 느린 스윙, 실타 14%: 낮은 타점) → v7.3 100%. 맞은 높이 0.2 m 99.8%, 0.16 m 97%.
- 로봇 스매시 스윙은 `SWING.AI_SMASH_SWING`(2.2 m/s)으로 따로 고정해 로봇 경기는 v7.2와 같다(회귀 지문 그대로).

## 회전 누적

$$S_{out} = \min\!\big(S_{cap},\; S_{base}(s) + k\cdot\max(0,\ S_{in}^{같은\ 종류})\big)$$

- 같은 종류: 드라이브 ← 들어온 탑스핀, 커트 ← 들어온 백스핀, 사이드 ← 들어온 횡회전 크기. 다른 종류는 쌓이지 않고 λ 효과만 받는다(`stackSpin`). 스매시·일반·블록은 쌓지 않는다.
- 결과는 `quality.stack = { spin, base, add, capped }`. 화면에 "회전 기본+누적 rps (MAX)", 상한이면 MAX SPIN 팝업.
- 측정(비행 1 s, 세기 1): 커트 55 → 70(상한), 드라이브 80 → 100(상한), 사이드 63 → 70(상한) — 둘째 타에 상한. 세기 0.5면 커트 40 → 61 → 70(셋째 타), 드라이브 55 → 75 → 82 → 85.

## 서브

| 버튼 | 서브 |
|---|---|
| 없음 | 무회전 서브 |
| Q / W / E | 탑 / 백 / 횡 서브, 회전 = 기본 회전 × `SERVE_SPIN_SCALE`(0.45) |
| R | 막음: 일반 서브(`quality.smashNoServe`, "서브는 스매시 불가") |

- 속도는 세기로 `SERVE_V_MIN~MAX`, 속도 보조·오차 축소는 그대로. 서브는 누적의 첫 타다.
- 서브 가이드라인(G)은 지금 누르고 있는 버튼의 서브를 그린다(R이면 일반).

## 조준 (6단계: 높은 포물선)

- 일반·드라이브·커트·사이드는 세기로 **목표 정점 높이** $H = H_{weak} + s\,(H_{strong} - H_{weak})$를 정하고 착지점·정점에 맞게 속도·발사각을 푼다(`solveArc`). 속도가 `*_V_MIN~MAX` 밖이면 한계 속도로 `solveAim`. 스매시는 가장 낮은 각.
- 목표 깊이는 구질별 `*_DEPTH`(위로 쓸수록 깊게 하던 `DEPTH_GAIN`은 없앰). 라켓 평면 범위·높이 한계는 6단계 그대로.
- 센 탑스핀은 빨리 떨어져 같은 깊이에 보내려면 빨라야 하므로, 누적된 드라이브는 `DRIVE_V_MAX`(5.8 m/s) 근처로 빠르고 짧다(측정: 누적 드라이브 평균 5.8 m/s·0.64 s, 누적 없는 드라이브 3.8 m/s·0.77 s).

## 터치 조작 (6단계 모바일 + 7단계 버튼)

- **오른손 엄지** = v6.2의 한 손가락 직접 조작 그대로(`touch.js`): 닿아 있음 = 마우스 버튼, 새로 대면 샘플을 비움, 뗀 뒤 `TOUCH_LIFT_HOLD` 유예, 캔버스 위 두 번째 손가락 무시, 서브는 화면을 대는 순간 토스.
- **왼손 엄지** = 화면 왼쪽 아래 2×2 구질 버튼(위: 드라이브·스매시, 아래: 커트·사이드, `MOB_BTN_SIZE` 64 px). 캔버스 밖 DOM 요소라 "두 번째 손가락 무시"와 충돌하지 않는다. 포인터를 붙잡아 손가락이 버튼 밖으로 미끄러져도 뗄 때까지 누름. `MOB_BTN_LEFT` 0이면 오른쪽(왼손잡이).
- 버튼 없이 쓸면 일반 스윙. 감도·오프셋·유예 값은 그대로다.
- **터치 스매시 기준** `TOUCH_SMASH_SPEED` 1.0 m/s(v7.1): 마우스 기준 2.0 m/s는 가로 휴대폰(844×390)에서 약 2 px/ms(화면 높이를 0.2 s에 쓸기)여서 엄지 스윙으로는 스매시가 계속 일반으로 떴다(사용자 피드백). 1.0 m/s ≈ 1 px/ms. 측정: 쓸기 0.8/1.2/1.6/2.0 px/ms → 판정 속도 0.84/1.27/1.65/2.05 m/s(시작 위치와 거의 무관). 입력 기기 값이라 "모바일" 묶음·대전 중 변경 가능(main.js가 터치일 때 `player.smashSpeed`로 넘긴다).

| 상황 | 샘플 | 이유 |
|---|---|---|
| 손가락이 닿아 있음 | `b = true` | 대고 멈추면 블록, 쓸면 스윙 |
| 손가락을 새로 댐 | 이전 샘플을 비움 | 순간 이동을 스윙 속도로 재면 오판 |
| 손가락을 뗌 | `TOUCH_LIFT_HOLD`(0.08 s) 동안 `b = true` | 튕기듯 쓸면 손이 먼저 떨어짐 |
| 구질 버튼 누름·뗌 | 그 순간 `k`를 바꾼 샘플 | 라켓이 멈춰 있어도 바로 반영 |

## 구조

- `input.js`: DOM 이벤트 → 샘플(`createMouseInput`), 순수 판정 `classifyShot(samples, ball, ctx)` → `{ shotType, vel, spin, quality }`, 버튼 상태 `createShotKeys`, `buttonAt`, `spinParts`, `incomingEffect`, `stackSpin`.
- `shotType`: `normal`·`drive`·`cut`·`side`·`smash`·`block`·`mishit`(`SHOT_TYPES`).
- 순수 함수만 `tests/input*.test.js`에서 테스트한다.

## 현실성 규칙

- 회전에 맞는 대응: 백스핀 → 드라이브(들어 올림)·커트, 탑스핀 → 드라이브·커트(백스핀으로 바꿈)·블록, 횡회전 → 사이드, 높은 공 → 스매시. 일반 스윙은 들어온 회전을 그대로 받는다(백 → 네트, 탑 → 떠서 아웃, 횡 → 옆으로).
- 타이밍(정점 대비 PERFECT/GOOD/OK/BAD)·방향 퍼짐(시드 있는 난수)은 그대로.

## AI 로봇 (ai.js)

- 궤적을 예측해 칠 자리로 가고, 같은 샘플(버튼 `k` 포함)을 만들어 `checkHit → classifyShot`으로 친다.
- **회전 읽기**(`readSpin`): 타격 예정 시각의 판정용 회전으로 종류(무·탑·백·횡)와 세기(회전 / 상한)를 읽는다(`AI_READ_MIN` 8 rps 미만은 무회전).
- **맞는 대응** 안에서 구질 비율(`AI_*_W_*`, 일반 `W_NORMAL` 포함)로 고르되, 확률 $(1 - \texttt{READ})(0.5 + 0.5\,L)$로 잘못 읽어 맞지 않는 구질(일반 포함)을 고른다(`misreadChance`). `READ`: 쉬움 0.6, 보통 0.9, 어려움 0.97 → 상한 회전에서 40% / 10% / 3%.
- 블록은 드라이브 버튼을 누른 채 멈춘다(제자리에 늦게 도착해 아직 움직이는 중이면 드라이브로 판정되게. 버튼이 없으면 일반 스윙이 되어 탑스핀 블록이 거의 다 아웃됐다).
- 스매시 방향은 판정과 무관하므로, 내려치기 시작점이 라켓 높이 한계(`Z_MAX`) 위면 올려 친다. 한계 근처(− 5 cm)보다 높은 공은 스매시하지 않는다.
- 서브는 무회전·탑·백·횡 중에서 비율로 고른다(스매시 없음).

## 기본 조작 모드 (v7.4)

설정 ⚙의 "조작 모드"에서 고른다(기본값 = 기본 모드, 이 브라우저에 `pp-control`로 기억). `classifyShot(…, { control: 'basic' })`이면 구질 버튼(샘플의 `k`, `ctx.button`)을 보지 않고 `judgeBasic`으로 판정한다. 로봇은 `control`이 없어 고급(버튼) 판정이다.

| 조건 | 결과 |
|---|---|
| 마우스 버튼 없음, 또는 스윙 최고 속도 < `BLOCK_SPEED` | 블록 |
| 아래로(sinθ ≤ −`DIR_SIN` 0.5), 속도 < `BASIC_SMASH_SPEED`(2.8 m/s, 터치 `BASIC_TOUCH_SMASH_SPEED` 1.4) | 커트 |
| 아래로 빠르게 + 빨간 고리(스매시 높이, 고급과 같은 `ringZ`·`SMASH_RING_FLOOR` 규칙) | 스매시 |
| 아래로 빠르게 + 노란 고리 | 센 커트 (v6.3 기본값 `LOW_SMASH_MISHIT` = 0과 같음, 실타 없음) |
| 곡률 \|κ\| ≥ `CURVE_MIN`(0.18) | 사이드 |
| 그 밖(위·옆) | 드라이브 |

- 일반(무회전)·조합 구질은 기본 모드에 없다. 서브: 위 = 드라이브 서브, 아래 = 커트 서브(빠르게 내려쳐도 스매시가 아니라 커트), 곡선 = 사이드 서브. 서브 가이드는 위로 휘두른 드라이브 서브.
- 값은 v6.3 그대로이고 `BASIC_TOUCH_SMASH_SPEED`만 새로 정했다(2.8 × v7.1 터치/마우스 비 1.0/2.0 = 1.4).
- 사람 클라이언트 전용이라 대전 중에도 바꿀 수 있고 두 사람의 모드가 달라도 된다(서버는 `vel`·`spin` 한도와 `shotType` 허용 목록만 검증).
- [x] (`tests/control-mode.test.js`) 대표 드래그 5종 → 드라이브·스매시·커트·사이드·블록 + 상대 코트, 버튼 무시, 낮은 공 빠른 내려치기 = 센 커트, 경계값, 터치 스매시 기준, 누적, 서브 3종·가이드, 모드 값 정규화.
