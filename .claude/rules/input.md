# 마우스 드래그 타격 시스템 사양

## 기본 조작

- **마우스 위치** → 라켓 위치(좌우, 높이)
- 시점에 따라 화면 1 px가 라켓 평면에서 움직이는 거리가 달라지므로, 사람의 드래그 속도에 `dragScaleFor`(기존 시점 mm/px ÷ 현재 시점 mm/px)를 곱해 판정한다. 같은 손놀림이면 시점과 무관하게 같은 구질·세기다(6단계). 로봇·서버는 1.
- **버튼 누른 채 휘두르기** → 스윙 기록 시작
- 스윙 중 라켓이 공에 닿는 순간 **타격** 발생
- 버튼을 누르지 않은 상태에서 공이 닿으면 약한 블록으로 처리

## 터치 조작 (6단계 모바일, v6.2)

`public/js/touch.js`가 터치를 마우스와 **같은 샘플 `{ t, x, y, b }`**로 바꾼다. `classifyShot`·`checkHit`·서버 판정은 그대로다. `pointerType === 'touch'` 이벤트에만 작동하므로 마우스 동작은 바뀌지 않는다.

| 상황 | 샘플 | 이유 |
|---|---|---|
| 손가락이 닿아 있음 | `b = true` (버튼 누름) | 대고 멈추면 조준 블록, 쓸면 스윙. PC와 같은 판정 |
| 손가락을 새로 댐 | 이전 샘플을 비우고 새로 시작 | 뗐다가 다른 곳에 대면 라켓이 순간 이동하는데, 이어서 재면 스매시 영역 속도로 오판된다 |
| 손가락을 뗌 | `TOUCH_LIFT_HOLD`(0.08 s = `SWING_WINDOW`) 동안 `b = true`, 그 뒤 `false` 샘플을 뗀 순간 미리 넣어 둔다 | 튕기듯 쓸면 공에 닿기 전에 손이 먼저 떨어진다. 그 뒤는 PC에서 버튼을 놓은 것과 같은 약한 블록 |
| 두 번째 손가락 | 무시 | 확대 동작·오입력 방지 |
| 서브 | 화면을 대는 순간 토스 (`onPress` 그대로) | |

- **라켓 오프셋**: 라켓은 손가락보다 `TOUCH_OFFSET_PX`(50 CSS px ≈ 8 mm) 위. 손가락이 들어오는 공을 가리지 않게 하고, 크게 하면 타점 아래에 위로 쓸어 올릴 자리가 준다.
- **터치 감도**: 판정 속도는 "화면 높이의 몇 %를 움직였나"에 비례하므로 작은 화면에서는 같은 손놀림이 훨씬 빠르게 재진다. 사람 드래그 속도에 `dragScaleFor`(시점) × `touchSpeedScale` = `TOUCH_SPEED_GAIN × 화면 높이 / MOBILE.TOUCH_REF_H(900)`을 곱한다. 같은 px/ms 스와이프는 휴대폰·태블릿에서 ±10% 안에서 같은 속도로 판정된다. 기본 `TOUCH_SPEED_GAIN` 0.7(추정): 1 px/ms ≈ 1.3 m/s, 스매시 2.8 m/s ≈ 2.2 px/ms.
- **임계값**: 방향(`DIR_SIN`)·곡률(`CURVE_MIN`)은 비율이라 화면 크기와 무관해 공용이다. 엄지 호(반지름 7 cm, 길이 3 cm)의 곡률 ≈ 0.05 < 0.18이라 사이드스핀으로 오판되지 않을 것으로 봤다. 오판 보고가 오면 터치 전용 값으로 나눈다.
- 터치 값(`TOUCH_*`)은 마우스 DPI처럼 각자 맞추는 입력 기기 값이라 대전 중에도 바꿀 수 있다(`TUNABLE_ONLINE_FREE`). 결과 공 속도·회전은 서버 한도 안에서 같다.

## 구조

- `input.js`는 DOM 이벤트를 받아 마우스 샘플 `{ t, x, y }` 배열로 만드는 부분과, 샘플 배열 → 구질 판정을 하는 **순수 함수** `classifyShot(samples, ballState)`로 나눈다.
- 순수 함수 부분만 `tests/input.test.js`에서 테스트한다 (클라우드 세션에는 마우스가 없음).
- 판정 결과는 `{ shotType, vel, spin, quality }` 형식으로 반환하고, 물리 엔진은 이것으로 공의 새 상태를 만든다.

## 구질 판정

접촉 직전 **약 80 ms 동안의 드래그 속도 벡터** `u`를 사용한다.
- 각도: `θ = atan2(u_y, u_x)`
- 세기: `|u|`
- 곡률: 드래그 경로의 휘어진 정도

| 드래그 | 판정 조건 | 결과 |
|---|---|---|
| 아래 → 위, 빠르게 | 위쪽 성분 큼, `|u|` 큼 | **드라이브**: 강한 탑스핀, 빠르고 바운드 후 뻗음 |
| 위 → 아래, 매우 빠르게 | 공 높이 > 네트 + `SMASH_MIN_HEIGHT`(6단계: 50 cm) | **스매시**: 최고 속도, 회전 적음, 화면 효과 최대 |
| 위 → 아래, 느리게 | 아래쪽 성분, `|u|` 작음 | **커트**: 백스핀, 낮고 느림, 상대를 네트에 걸리게 유도 |
| 좌우, 휘어진 궤적 | 곡률 큼 | **사이드스핀**: 바운드 후 옆으로 꺾임 |
| 거의 정지 | `|u| ≈ 0` | **블록**: 상대 공의 힘과 회전을 반사 |

모든 판정 임계값은 `constants.js`의 `TUNABLE`에 둔다.

## 조준 (6단계: 높은 포물선)

- 드라이브·커트·사이드는 세기 $s$로 **목표 정점 높이** $H = H_{weak} + s\,(H_{strong} - H_{weak})$ (`*_APEX_WEAK`/`*_APEX_STRONG`)를 정하고, 착지점과 정점이 맞도록 속도·발사각을 함께 푼다(`solveArc`, 속도 벡터 3성분 뉴턴법, 약 1 ms). 약하게 치면 높고 느리게, 세게 치면 낮고 빠르게 간다.
- 필요한 속도가 `*_V_MIN~*_V_MAX` 밖이면 한계 속도로 기존 조준(`solveAim`, 목표에 닿는 가장 낮은 각)을 쓴다. 스매시는 항상 가장 낮은 각(빠르게 꽂힘).
- 이유(v5.2 실패 원인): 속도만 낮추면 엔드라인 뒤 타점 + 가장 낮은 각 선택 + 비거리 한계로 네트·투 바운드가 늘었다. 높은 포물선은 네트 여유가 커서 늦게·낮게 쳐도 잘 들어간다.
- 라켓 평면 범위 `SWING.Y_MIN`~`Y_MAX` = 엔드라인 뒤 0.3 m ~ 탁구대 안쪽 0.67 m (짧게 떨어진 공은 탁구대 위로 손을 뻗어 친다), 높이 한계 `Z_MAX` 1.3 m.
- 스매시 기회: 공이 높게 날아 바운드도 높아졌으므로 `SMASH_MIN_HEIGHT`를 0.5 m로 올렸다. 약하게 높이 띄운 공이 상대의 스매시 기회가 된다.

## 현실성 규칙

- **상대 회전의 영향**: 들어온 공의 회전이 반사 방향에 영향을 준다. 백스핀 공을 블록하면 아래로 떨어져 네트에 걸린다. 회전에 맞는 대응을 해야 한다.
- **타이밍**: 바운드 정점에서 치면 `PERFECT`(정확도↑). 너무 이르거나 늦으면 방향이 퍼진다.
- **스매시 조건**: 공이 높을 때만 가능하다. 낮은 공을 내려치면 네트에 걸린다.
- **방향 퍼짐**: 정확도가 낮을수록 목표 방향에 오차를 준다. 오차는 결정론을 위해 시드가 있는 난수 생성기(인자로 전달)로 만든다.

## AI 로봇 (ai.js)

- 공의 궤적을 물리 엔진으로 미리 계산해 칠 위치로 이동한다.
- 난이도는 반응 지연, 이동 속도, 구질 선택 다양성으로 조절한다(쉬움·보통·어려움).
- AI도 사람과 같은 `classifyShot` 경로를 거쳐 공을 친다(가상 마우스 샘플 생성). 그래야 AI끼리 대결이 실제 판정 테스트가 된다.
